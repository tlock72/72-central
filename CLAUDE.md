# 72 Central: working notes for Claude

Read this first instead of re-reading every script. It is an internal site for SeventyTwo Sports Group, owned by Tobey (tlock72).
It is hosted on GitHub Pages at tlock72.github.io/72-central and protected by a passcode screen in `index.html`.

## Hard rules
- **Zero budget.** Everything runs free on GitHub Actions and cron-job.org. Never add paid services.
- **No Claude dependency.** All updates must run without Claude in case the subscription lapses.
- **Accuracy over completeness.** Bosses use the site, so never guess a score or ranking. Leave it blank and alert instead.
- **Live Tennis API free plan: 100 calls a day.** `update.py` caps each run at 45 (`MAX_CALLS`). A normal day uses about 45–50, and a busy Monday up to about 85. Runs started by hand always run (only timer runs skip if the site updated in the last 20 minutes), so they burn calls.
- **Tennis Europe data:** used with permission from Tennis Europe, internal use only. Keep `robots.txt` blocking indexing.
- Tobey edits in the GitHub web editor, so keep changes small and explain them in plain English.
- **Google Sheet script (`scripts/visit_log.gs`) changes:** always give Tobey the direct GitHub link to the file on the branch it was pushed to (`https://github.com/tlock72/72-central/blob/<branch>/scripts/visit_log.gs`), so he can use "Copy raw file" at the top right and paste it over the whole script. Remind him to deploy a new version afterwards.

## Scripts (`scripts/`)
- `espn.py`: ESPN's free public scoreboard (`site.api.espn.com/apis/site/v2/sports/tennis/{atp,wta}/scoreboard?dates=`), no key, no daily limit. The main source for ATP and WTA matches: tour events, their qualifying and WTA 125s (not Challengers, ITF or juniors). 6 calls a run (yesterday, today, +6 days, for each tour). Categories come from `schedule.json` by city and date, else from what `data.json` already had for that tournament. Only ESPN's own "final + winner" makes a match finished.
- Times on the site (in `index.html`, `twoTimes`/`evZone`): data stays in UK time, but the page shows each viewer's own time (the device's zone, or the one picked in Settings: the cog in the top corner, which also changes the first name; both saved on that device as `72c-tz`/`72c-name`, `MYTZ` in the code), and for match start/finish times also the local time where the event is played. The event's place comes from `schedule.json` (city in the tournament name + dates) or the tournament name itself; nation → time zone is in `TZ_NAT`, and nations with several zones (USA, Canada, Australia, Spain's Canaries, Brazil, Mexico…) need the city or US state (`TZ_CITY`/`TZ_US`). If the zone isn't certain, UK time is shown instead. "Today", "Tomorrow" and "this week" on the Competition Zone, home page and roster follow the viewer's own date (`myDate`, `md(m)`: a match's day from its start time, or with no time, its UK date moved by the viewer's day difference from the UK); an event time on another day gets the weekday added ("Tue 15:30"). The scripts and the ESPN live check still work in UK dates.
- Live scoreboard (in `index.html`, `espnLive`): while the home page or Competition Zone is open, the browser itself reads the same ESPN scoreboard once a minute and updates the ESPN matches in `data.json` (live set/game scores, finals with the same "final + winner" rule, and a new start time if ESPN moves a match that hasn't started). Nothing is saved and no GitHub runs or Live Tennis API calls are used. If ESPN can't be read, the page says so and falls back to the regular data; live scores older than 3 minutes aren't shown.
- `update.py`: Live Tennis API for Challengers, ITF and juniors, plus ESPN (above) for ATP/WTA. No feed lookups are spent on a match ESPN has; where both list a match ESPN's copy is kept; if ESPN can't be read the Live Tennis API covers everything as before. Runs a live check hourly (the :13 run), upcoming matches every 2 hours, and result lookups capped per run.
  - **Rankings** follow the official week: they only fetch when `scouting.json` shows a newer ATP/WTA week than `rankingsTourWeek`.
  - It first probes 3 top players. If their points are unchanged, the feed is lagging, so it retries in 2 hours (and from Wednesday accepts whatever the feed has).
  - It then publishes each tour all at once.
- `scouting.py`: free sources, no key. ATP comes from Tennis Abstract (`reports/atpRankings.html`, "Last update" date) and WTA from `api.wtatennis.com` (`rankedAt`). Ranking points: WTA from the same feed; ATP from Tennis Explorer's list of the same week (Tennis Abstract has none), tried every run until that week is out there, kept only for players Tennis Explorer ranks exactly as Tennis Abstract does (90%+ must agree). Points that don't go down with the rank are dropped (blank) and alerted (`errors.atpPts`/`wtaPts`); a failed ATP read is retried once a day (`ptsFailed`). 72 Rankings uses the score feed's points, else these (same rank only). It checks hourly on Mondays and Tuesdays and every 3 hours otherwise (every run while old ATP weeks are still being filled in from Tennis Explorer). **It is also the "is a new ranking week out?" signal.**
- `itf_juniors.py`: ITF junior rankings, weekly. It stops immediately at the ITF bot check and never bypasses it.
- `itf_jr_list.py`: the full ITF junior boys and girls ranking lists (`PlayerRankApi/GetPlayerRankings`, 100 a page, 6 s apart), run in `itf-juniors.yml` right after `itf_juniors.py`. The list has no date, so the week is `rankDate` in `itf.json`, and the list is only saved if every 72 junior read for that week has the same rank in it. Bot check = stop and keep the previous list.
- `te_rank_list.py`: Tennis Europe Ranking "Boys/Girls 14 & Under" lists (`/ranking/ranking.aspx?rid=79` for the week list and category ids, then `/ranking/category.aspx?id={week}&category={cat}&p=&ps=100`), run in `prospects.yml`. Checks at most every 3 hours (one request) and rebuilds only when a new week is out; reads the 1 wk / 3 mo / 12 mo past weeks once each. Every page must show the same week in its heading and "Last updated" date, or nothing is saved.
- `itf_matches.py`: ITF junior draws and results. A full check of every junior about twice a day (`tried`/`checked` in `itfm.json`). In between, a quick check every hour (`quick`) re-reads only the juniors with a match today or earlier that isn't finished yet, so results show within about an hour. After the ITF bot check (`blocked`) it waits 3 hours. Juniors whose request fails keep their previous matches.
- `itf_titles.py`: ITF singles titles for the whole roster from the ITF site (circuit `MT` men / `WT` women, singles, main-draw finals won; ITF World Tennis Tour plus pre-2019 Futures and ITF Women's Circuit). Loads each player's whole career once, then the current year daily from 07:00 UK, and career highs weekly. Stops at the ITF bot check and never guesses an unreadable final.
- `te_matches.py`: Tennis Europe matches, once a day from 07:30 UK.
- `schedule.py`: Tour Schedule, once a day (`schedule.yml`). Calendars: ATP Tour and Challenger from Wikipedia's "2026 ATP Tour" / "2026 ATP Challenger Tour" pages (atptour.com blocks GitHub; its calendar PDF has a fixed January name), WTA + WTA 125 from api.wtatennis.com, ITF men/women/juniors from the ITF calendar API, Tennis Europe from its tournament search. 72 entries (events up to 4 weeks ahead): ITF acceptance lists matched by ITF id (`titles.json` ids + `itf.json`), WTA player lists by name, Tennis Europe: each event's entry list, then acceptance list (`/sport/acceptancelist.aspx`, one page per age group, switched with the page's own form; matched by the profile ids in `te.json`, withdrawn left out; on the preliminary entry list a junior is just "Entered"; junior profiles only list tournaments already played, so they can't be used), ATP/Challenger: shown if **any one** of live-tennis.eu `/en/atp-schedule` (top ~1,000 men, next 3 weeks), Tick Tock Tennis `/atp` (every list incl. qualifying and withdrawals; older than 6 days counts as failed) or Spazio Tennis (WordPress API, category `ent`: official main-draw acceptance lists + alternates, struck-through/"OUT" = withdrawn, "IN" = alternate got in; headings in Italian, matched to the coming event in the same city (`IT_CITY` translates Pechino, Firenze...) and only used if most of its players are also down for that event on the other sites, or on its own when neither other site covers that event, if it is this year's list posted in the 10 weeks before an event that hasn't started) lists the player; a withdrawal on Tick Tock or Spazio always wins. When the sites disagree on main draw / qualifying the label is just "Entered". An event running over two weeks (Shanghai, Indian Wells...) matches a site's list in either week. Once an event has started and the sites have moved on, yesterday's entries are kept until ESPN's draw replaces them. If a Slam or 1000 list is out (30+ names) without one of our top-40 men on it or on any other event that week, `checks[]` in `schedule.json` gets a message and `report_gaps.py` alerts it once. Week columns are worked out each run by matching names to the calendar. One or two sites failing is alerted and the rest still count; all three failing keeps yesterday's entries. Then "In the draw" from `data.json`, and from ESPN's published draws for ATP/WTA/WTA 125 events (`espn_draws`: every 72 player placed in the draw, including byes and TBD opponents; "Qualifying draw" if only in qualifying). Never uses the Live Tennis API. A failing part keeps its previous events and is alerted.
- `prospects.py`: Scouting Corner. Links each prospect across stages without guessing: the ITF id is the anchor (one id covers juniors and pros; exact full name + nationality, more than one fit = `unsure`, alerted), Spelling: names are tidied (capitals) and, once linked, shown with the ITF's spelling; a name the ITF doesn't have is checked against ITF players one letter out (each word searched): exactly one, with the typed nationality = linked under the ITF spelling and alerted; otherwise only a "Did you mean…?" alert. Tennis Europe by exact name + the nationality flag on the profile (never searched for anyone born before 2010, i.e. over 16: link, ranks and results dropped, Tennis Europe box hidden on the card; a missing year of birth is read from the ITF's `GetHeadToHeadPlayerDetails` (a field labelled birth, `bornFrom` "ITF"), else from the Tennis Europe profile when clearly labelled, `bornFrom` "Tennis Europe"), ATP/WTA by the rank the ITF shows for that id matched to the same rank and surname in `scouting.json`. Links are kept; missing stages are re-checked weekly (or at once when the name/nationality changes), so a player moving up a level is picked up. Reads ITF `GetPlayerOverview` (JT, MT/WT) and `GetPlayerActivity` (12 months), Tennis Europe `/player-profile/{id}/ranking` (the "Tennis Europe Ranking" table, never the Race to Monte-Carlo one below it) and `/tournaments`. Past Tennis Europe weeks for the moves (1 wk, 3 mo, 12 mo back) come from `/ranking/player.aspx?id={week}&player={id}` (week ids from `/ranking/ranking.aspx?rid=79`), read once each (`hist.teTried`) and only kept if the page's player, week label and "Last updated" date all agree. The ITF has no past weekly junior ranks (its ranking API has no date), so ITF junior moves only build up from when a prospect is added. New names every run, everyone daily from 05:00 UK, 25-minute budget, 5 s between requests, bot check = that site left alone 3 hours. Only writes `corner.json` when something changed.
- `lookup_results.py`: "12 months" on Filtered Rankings, on request (`results.yml`). Reads the Sheet's last 3 days of requests (`?kind=lookups`), finds each player on its own ranking list (never trusts what the page sent), then: ATP/WTA via the ITF id by name + nationality (`itf_id` from `suggest_results.py`, kept from earlier files or `suggest.json`; `NO_ITF_LINK` applies), ITF juniors via the id in the list's link (junior + pro matches), Tennis Europe U14 via the profile link. Once a day per player, 12-minute budget, bot check = that site left alone 3 hours.
- `best_ranks.py`: past best rankings for those over-21 suggestions. Keeps the official ATP (Tennis Explorer) and WTA (api.wtatennis.com, by player id) top 700 at the first Monday of each quarter over the last 5 years, 3 quarters a run until all are in (past lists never change), and writes each over-21 top-1000 player's best from those more than 12 months back to `best.json` (`old`; 0 = never top 700; `ready`; `errors` alerted).
- `news.py`: News, from free public RSS feeds (`FEEDS`: BBC Sport, The Guardian, Sky Sports, The Independent, The Telegraph, Tennis Majors, Tennis365, Ubitennis; plus, for business only (`BIZ_FEEDS`), SportsPro, Sportico, Front Office Sports and three Google News searches (results shown under the outlet that ran them, outlets already read directly left out); ESPN, Eurosport, SportBusiness, Reuters, the ITF and LTA do not serve GitHub). Business / tournament stories (`topic()`: word lists `BIZ`, `EV`, phrases; a match verb or "ranking points" in the headline keeps it a match story) rank higher (`BONUS`), are kept a week and have their own top 40; from `BIZ_FEEDS` only those are kept (sport-wide outlets must also name tennis/ATP/WTA...). Headlines from the general outlets must be about tennis (a tennis word, an "… Open", a top-500 surname from `scouting.json`, or a 72 player/prospect); the same story is grouped when headlines share two ranked players, or one plus 3 key words, within 36 hours. Keeps 3 days (a week for stories naming a 72 player or prospect, matched by full name, any accents), also groups headlines with 3+ key words in common (60%+ of the shorter one); then folds together pieces on the same match or moment even from the same outlet (headline + summary, compared with the group's lead only so stories can't chain across a tournament: within 12 hours and the same two ranked players, or one plus 3+ other key words that aren't player names; the best-covered version leads, the rest are "Also" links, numbered if one outlet has several); top 40 plus all 72/prospect stories. Only writes when something changed. A feed unreadable for 2 days is alerted; to drop or swap one, edit `FEEDS`.
- `market.py`: Market map, right after `news.py` in `news.yml`. Tags business / tournament stories with countries by the words in `PLACES` (country, people, cities, tournaments, federation; ambiguous ones like Georgia, Nice, Santiago, "Indian" left out): news.json stories by headline or summary, plus two Google News searches per country (`tennis "<country>"` + business words, and `SECTOR_QUERY`: investment / business moves in sport, tech, food, insurance, healthcare, plus war news; 7 days), 8 countries a run, oldest first, our players' nations first and about twice as often; a sector story (`sector()`, word lists `SECTORS`, needs a money word `W_MONEY` unless it's war news, share-price notes dropped) must name the searched country in its headline; a search result is kept for the searched country only if its headline names it or no other country. Same story grouped (best outlet leads, `news.BEST`); score = outlets (max 6) + 2 business / 1 tournament / 0 sector + 2 if the headline names the country − 0.6 a day. A ranked surname only counts as "tennis" when not used as a first name (`news.pro_named`: "Donald Trump" is not Matthew Donald).
- `brands.py`: Market map "Brands on the move", after `market.py` in `news.yml`. Two Google News searches per market (sponsorship news; business moves: marketing bosses, expansion, launches, funding, results), roster nations every ~5 hours and the big markets every ~10 (`EVERY_H`), 10 searches a run; a headline stays in the market searched unless it names only other countries (`market.places`). Known brands are matched by name in the headline (`BRANDS_TXT`, by sector, aliases with "/"; names that are everyday words or surnames need a longer form or a pattern in `SPECIAL`, e.g. Visa, Emirates, Hilton, Zara). Signals from headline words (`signals()`; `W_NOISE` drops wars, politics, crime, share-price notes and "employer-sponsored" visas). A headline naming another country (`market.PLACES` or any country name in `worldmap.json`) is dropped from the market searched; one naming no country is kept only if no other market's search found it and it doesn't say "global"/"worldwide"/"markets" (otherwise it's world news). "Other business moves" need a clear move ("opens" alone or bad news alone isn't one). Brands named in exactly the same headlines share a card. To add a brand or market, edit `BRANDS_TXT` or `ROSTER_NATS`/`BIG` (a new market also needs its words in `market.PLACES`).
- `report_gaps.py`: alerting. Also compares each roster player's current ranking in `data.json` with the official list in `scouting.json` (same week only) and alerts a mismatch. It comments on the GitHub issue "72 Central: missing info" (GitHub emails Tobey) and reports each message once, so **never put times in alert text**. It also runs as the watchdog.

## Workflows (`.github/workflows/`)
- `update-scores.yml`: runs every 30 minutes (cron `13,43 6-22 * * *` UTC, plus cron-job.org dispatches with `source=timer`). It runs update.py, then ITF ranks if due, scouting, ITF matches, TE, save, and alert.
  - Checkout uses `ref: main`, because a run queued behind another must start from the newest data.
  - The save step does `pull --rebase -X theirs`, and on failure aborts and skips (the next run catches up).
- `itf-juniors.yml`: Mondays at 08:20, 11:20 and 14:20 UK. Also runs `itf_jr_list.py` (Filtered Rankings' junior lists).
- `schedule.yml`: daily at 06:37 UK. Has its own concurrency group (it must not hold up live scores); it only saves `schedule.json`, so its pull-rebase save can't clash with the score updates. Takes about 30–40 minutes (ITF and Tennis Europe lists, one every 4 seconds).
- `prospects.yml`: Scouting Corner, every 30 minutes (`7,37`) and on dispatch from the Sheet. Own concurrency group; saves only `corner.json` and the Tennis Europe U14 lists (`terank.json`, `te_rank_list.py`). Ticking "force" on Run workflow sets `FORCE=1`: everyone is refreshed at once, even if already done today.
- `results.yml`: Filtered Rankings' "12 months" look-ups (`lookup_results.py`), on dispatch from the Sheet and every 30 minutes (`22,52`) in case a start was missed. Own concurrency group; saves only `results/`.
- `news.yml`: News, hourly at :27 (06:27–23:27 UK summer time), then the Market map (`market.py`, `brands.py`). Own concurrency group; saves only `news.json`, `market.json`, `market_pool.json`, `brands.json` and `brands_pool.json`.
- `watchdog.yml`: every 3 hours. Alerts if updates stop, runs keep failing, or Pages fails to build.
- `check-api.yml`: a one-off API shape check (`discover.py`).

## Gotchas already hit
- Commits made in the GitHub web editor can land while a run is mid-flight. That's handled by `ref: main` and the rebase fallback.
- Feed rankings lag official rankings by hours on Mondays, which is why rankings use the official-week check and probe.
- Mid-week of two-week events, the tours publish no new ranking. That's normal, and no calls are spent.
- `ubuntu-latest` moves to Ubuntu 26 from 19 Oct 2026. If something breaks after that, check Python/pip first.

## Testing without spending calls
Monkeypatch `update.api` with a fake that returns `{"data": ...}` and run `update.main()` on a copy of the repo. Never run with the real key just to test.
